# UI/UX Baseline Assessment & Gap Analysis

## 1. Executive Summary

This document evaluates the user experience, information architecture, and language presentation of the **SOC Detection Lab Web Console** (`dashboard/app.py`, running on port 8501) prior to the specialized UI/UX and Korean interpretation enhancement.

The primary objective of this assessment is to identify cognitive friction points for Korean Tier 1 / Tier 2 security analysts and define structural improvements without mutating underlying detection logic or evidence immutability.

---

## 2. Technical Stack Inventory

| Component | Pre-Change State | Technical Evaluation |
|---|---|---|
| **Backend Framework** | FastAPI (Python 3.13) | Lightweight, asynchronous, high-throughput REST API. |
| **Frontend Architecture** | Server-rendered Single Page HTML via `HTMLResponse` | Self-contained, zero build step required (`npm`/`webpack` free), portable. |
| **Styling** | Tailwind CSS (CDN) | Utility-first CSS, responsive flex/grid layouts. |
| **Visualization** | Chart.js (CDN) | Doughnut & Pie charts for attack categories and engine distribution. |

| **State Management** | Vanilla JavaScript & DOM updates (`setInterval` 3s) | Direct DOM mutations, polling REST endpoints (`/api/stats`, `/api/incidents`, etc.). |

## 3. UI/UX Gaps & Cognitive Friction Points Identified

### Gap 1: Inconsistent Language Mixing & Unexplained Technical Jargon
- **Observed State**: UI labels mixed English technical terms (`Observed Facts`, `Unknowns`, `Correlated Incidents`, `HITL Proposals`) with Korean descriptions (`정찰부터 C2 비콘까지...`).
- **Cognitive Impact**: Analysts had to mentally translate signature patterns (`SOC-SCAN: Nmap Stealth NULL Scan Detected (Zero Flags)`) and lacked immediate clarity on the operational impact of the alert.
- **Remediation**: Establish a dual-tier localization architecture:
  1. A deterministic Korean terminology dictionary.
  2. A dedicated `[원문]`, `[한국어]`, `[나란히 보기 (Split)]` segmented view mode.

### Gap 2: Conflation of "Detection" vs. "Confirmed Compromise"
- **Observed State**: High-severity alerts and incident cards displayed verdicts without explicitly clarifying whether an attack succeeded or was merely observed as an attempt.
- **Cognitive Impact**: Analysts could mistakenly conclude that an internal host was compromised upon seeing a `Web SQL Injection` attempt.
- **Remediation**: Introduce an explicit **Compromise Status** indicator in alert/incident interpretations, stating clearly:
  > *"경보 발생 상태 (공격의 실제 침해 성공 여부는 웹 서버 응답 코드 및 응답 크기 추가 검증 필요)"*

### Gap 3: Ambiguity in Action Approval Buttons (`[승인]` vs. `[모의 실행 승인]`)
- **Observed State**: The HITL containment table had a simple green button labeled `✅ 승인 (Dry-Run)`.
- **Cognitive Impact**: Analysts or auditors could confuse this with applying live, persistent blocking rules to production gateway firewalls.
- **Remediation**: Explicitly label buttons as `✅ 모의 실행 승인 (Dry-Run)` and display warning confirmation dialogs explaining that no live host kernel modifications will occur.

### Gap 4: Provider Transparency (`AI Copilot: Active` vs. `Mock Baseline`)
- **Observed State**: Header badge displayed `AI Copilot: Active`, which did not indicate whether the response was generated by a live local LLM (`Ollama qwen2.5:7b`) or the deterministic `MockLLMProvider` baseline.
- **Cognitive Impact**: Misleading impression of LLM capabilities when running in offline/CI environments.
- **Remediation**: Add explicit provider transparency indicators (`모의 분석 기준선 (Mock Baseline - 실제 LLM 아님)` vs. `로컬 LLM (Ollama 활성)`).

### Gap 5: Absence of Visual Attack Timelines
- **Observed State**: Multi-stage attack chains were rendered as simple text tags (`⚡ 1. Reconnaissance`, `⚡ 2. Initial Access`).
- **Cognitive Impact**: Difficult to follow the sequential progression of an adversary through the killchain over time.
- **Remediation**: Build a visual step-by-step attack timeline with color-coded stage badges, timestamps, and detection engine icons.

### Gap 6: Lack of Evidence Payload Inspection
- **Observed State**: Alert tables showed IPs and signatures, but clicking an alert did not reveal HTTP URIs, User-Agents, or raw flow payloads without querying OpenSearch directly.
- **Cognitive Impact**: Slowed down forensic triage.
- **Remediation**: Implement a modal-based **Evidence & Payload Inspector** for deep-dive packet inspection.

---

## 4. Preservation Boundaries (Non-Negotiable Invariants)

1. **Evidence Immutability**: Raw alert payloads (`eve.json`, `alert_json.txt`), timestamps, IPs, SIDs, and packet metadata must never be overwritten or mutated by the localization layer.
2. **Deterministic Policy Priority**: Policy validation must continue executing on the server before human review.
3. **Dry-Run Enforcement**: All actions remain in simulation mode.
4. **Zero API Regressions**: All 47 existing tests must continue passing without breaking changes.
