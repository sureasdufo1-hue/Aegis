## 1. 사업 개요

### 1.1 추진 배경 및 목적
본 평가는 보안관제 탐지·분석 환경(Suricata/Snort, Wazuh SIEM, Correlation Engine) 상에 연동된 **로컬 독립 AI 추론 플랫폼(Ollama Native)의 실제 LLM 모델들(Qwen3.5 9B 및 Qwen3.5 4B)과 기준선 모의 엔진(Mock Baseline)**을 대상으로 침해사고 조사 품질, 추론 지연, 자원 소비율, 보안성 및 정책 준수율을 체계적으로 검증하기 위해 수행한다.  
의뢰인의 구현계획서(`SOC-AI-LLM-IMP-001`)에 기반하여 객관적 실측 데이터와 정량적 지표를 도출하고, 관제 실무에서의 최적 운영 전략을 수립한다.

### 1.3 기준 적용 원칙 및 평가 한계
1. **실측 중심 원칙**: 모든 지표(메모리 점유, 토큰 생성 속도, 지연시간)는 실제 Windows 11 호스트의 Xeon E-2374G CPU 환경에서 직접 계측된 수치만을 기록한다.
2. **독립성 및 무손실 원칙**: 기존 구동 중인 Wazuh SIEM(Manager, Indexer, Dashboard) 및 관제 대시보드(Port 8501)에 부하 간섭이나 설정 변경을 일체 가하지 않는다.
3. **하드웨어 한계 명시**: 호스트에 외장 전용 GPU(NVIDIA CUDA 등)가 없으므로 100% AVX2 CPU 기반 추론을 수행하며, 측정 속도는 CPU 연산 대역폭의 한계를 반영한다.

## 2. 수행 방법

### 2.1 분석 방법 및 절차

```text
[단계 1: 런타임 및 무결성 진단]
  Ollama v0.33.3 런타임, 로컬 바인딩(127.0.0.1:11434), model-lock.json 해시 검증
      ↓
[단계 2: 단독 Smoke 벤치마크]
  합성 보안 이벤트 및 Structured JSON 모드(think=False)를 통한 9B/4B 속도 및 메모리 실측
      ↓
[단계 3: RAG 및 읽기 전용 도구 연동 검증]
  Threat Intel 조회(lookup_threat_intel), RAG 청크 바운딩(max_chars_per_chunk=800) 계측
      ↓
[단계 4: End-to-End 침해사고 전체 루프 실증]
  다단계 복합 공격(NULL Scan + Web SQLi) 실데이터 투입 후 Pydantic 스키마 및 정책 검증
      ↓
[단계 5: 비교 평가서 및 비상 롤백 런북 도출]
  정량 지표 매트릭스 확정, 비상 복구 절차 수립, 최종 Release Gate 판정
```
