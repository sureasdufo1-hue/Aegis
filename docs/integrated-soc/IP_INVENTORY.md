# IP_INVENTORY — 관측 주소와 물리망 기준

## 현재 호스트/VM 관측

| 위치 | 관측 주소 | 확인 방법·한계 |
|---|---|---|
| Windows 물리 이더넷 | `10.10.70.151/25`, GW `10.10.70.129` | `Get-NetIPConfiguration`/route; M1/M2 관리자 PC `.10.2` 아님 |
| Windows 두 번째 이더넷 | 비활성, IP 없음 | 로컬 어댑터 상태 |
| VMnet10 / VMnet8 / VMnet1 | `10.77.10.1/24` / `192.168.111.1/24` / `192.168.135.1/24` | 로컬 VMware 가상 NIC |
| `soc-sensor` / `soc-gateway` | `10.77.10.20` / `192.168.111.140` | VMware Tools가 보고한 게스트 대표 IP |
| `soc-victim` / `soc-siem` | `10.77.30.100` / `10.77.10.30` | 동일; 전체 NIC/라우트 아님 |
| `soc-attacker` | 미확인 | Tools 조회에서 주소를 얻지 못함 |

## M1/M2 물리 배포 목표(실제 할당 확인 전에는 IP 변경 금지)

| 구간/역할 | 목표 주소 | 구별할 점 |
|---|---|---|
| 실습 외부망 / 상위 GW | `10.10.70.128/25` / `.129` | 현 Windows PC도 외부망 `.151`에 있음 |
| TrusGuard eth1 WAN | `10.10.70.214/25` | 실제 인터페이스 주소 |
| SNAT 객체 / WEB VIP 객체 | `10.10.70.163` / `10.10.70.164` | NIC 주소가 아닌 NAT 객체; 구 WEB VIP `.152` 사용 금지 |
| TrusGuard eth2 ↔ L3 Gi1/0/24 | `192.168.40.1/30` ↔ `.40.2/30` | Transit |
| TrusGuard eth3 ↔ Web | `172.16.10.1/24` ↔ `.10.10/24` | DMZ |
| VLAN10 SVI / Admin / VM1 / L2SW2 관리 | `192.168.10.1` / `.10.2` / `.10.101` / `.10.12` | Admin PC는 현재 PC와 동일하다고 증명되지 않음 |
| VLAN20 SVI / PC / VM2 | `192.168.20.1` / `.20.2` / `.20.101` | 사용자망 |
| VLAN30 SVI / DB / LOG | `192.168.30.1` / `.30.2` / `.30.3` | 구 DB `.30.10`, LOG `.30.20` 금지 |
| Analyse PC1 ↔ L3 Gi1/0/4 | `192.168.40.6/30` ↔ `.40.5/30` | Transit `.40.0/30`과 별도 `/30` |
| Analyse PC2 수집 NIC | **L3 IP 없음** | Gi1/0/13 SPAN 목적지; GW도 없음 |
| Analyse PC2 관리 NIC / 신규 SOC 서버 | **미배정** | 사용 가능 주소·점유·ACL·승인 조사 후 지정 |

`10.77.*`와 M1/M2 주소를 전역 검색·치환하지 않는다. 독립 Lab을 보존하고 물리 배포 프로파일만 새 주소를 사용한다. 네트워크 변경 전에 현장 `show`, ARP, 라우트, IP 충돌, 백업/롤백 자료가 필요하다.
