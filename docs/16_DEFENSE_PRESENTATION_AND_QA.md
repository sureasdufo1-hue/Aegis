## 2. 심층 기술면접 15대 디펜스 질의응답 (Deep Technical Interview Defense Q&A)

### Q1. 왜 Suricata와 Snort를 둘 다 사용했습니까? 단일 IDS로 충분하지 않습니까?
- **답변 요약:** **실시간 고속 탐지와 오프라인 심층 교차 검증의 역할 분담** 때문입니다.
- **상세 디펜스:**
  - **Suricata 8.0.6:** 멀티스레드 `AF_PACKET` 클러스터 모드로 작동하여 기가비트급 실시간 트래픽을 패킷 손실 없이 캡처하고 구조화된 `eve.json`으로 스트리밍합니다.
  - **Snort 3.12.2.0:** 싱글/멀티스레드 하이브리드 아키텍처와 C++ 기반 `libDAQ 3.0.27`을 탑재하여 수집된 PCAP 원본에 대해 오프라인 심층 정규식 매칭을 수행합니다.
  - 단일 벤더 탐지 엔진에만 의존할 경우 발생할 수 있는 파서 취약점이나 룰 오탐을 상호 교차 검증(Cross-Verification)하여 탐지 신뢰도를 극대화했습니다.

---

### Q2. 센서 VM의 모니터링 NIC에 왜 IP 주소를 할당하지 않았습니까?
- **답변 요약:** **공격자의 탐색을 회피하고 센서의 보안성을 완벽히 보장하기 위한 스텔스 탭(Stealth Tap) 구성**입니다.
- **상세 디펜스:**
  - 모니터링 인터페이스(`ens37`, `ens38` 또는 `ens224`)에 L3 IP 주소가 부여되면 공격자가 ARP 스캔이나 ICMP 스위프 시 센서의 존재를 인지할 수 있고, 센서 OS의 네트워크 스택 취약점을 통한 공격 표면이 노출됩니다.
  - 따라서 IP를 완전히 배제하고 오직 L2 프롬스큐어스 모드로 패킷 프레임만 버퍼에 복사하도록 구성하여 센서의 은닉성과 무손실 수집을 보장했습니다.

---

### Q3. Wazuh 4.14.7에서 부모 룰 상속 단절 버그는 무엇이며 어떻게 해결했습니까?
- **답변 요약:** **기본 내장 룰 `86601`이 EVE JSON을 선점하여 커스텀 룰의 체이닝이 끊어지는 결함을 복합 `<if_sid>` 선언으로 해결**했습니다.
- **상세 디펜스:**
  - Wazuh 내장 Suricata 디코더 룰 `86601`이 알림 이벤트를 가로채면서, 사용자가 정의한 부모 룰(`100100`)을 상속받아야 할 자식 룰(`100101~100103`)이 트리거되지 않는 단절 버그가 발생했습니다.
  - 이를 해결하기 위해 `local_rules.xml`에서 단일 상속 대신 `<if_sid>86601,100100</if_sid>`로 복합 부모 ID를 지정하여, Suricata 원시 이벤트와 Wazuh 내부 이벤트가 끊김 없이 다계층 상관분석 체인으로 이어지도록 보정했습니다.

### Q4. AI Security Gateway에서 단순 정규식(Regex) 외에 어떤 가드레일을 적용했습니까?
- **답변 요약:** **5계층 심층 가드레일(구문 격리, 의미 분류, Pydantic 스키마 강제, 정책 판정, 출력 정화)**을 적용했습니다.
- **상세 디펜스:**
  1. **구문 격리:** 프롬프트 템플릿 내에 `<user_data>` 및 `<system_boundary>` 토큰을 강제 주입하여 공격자가 지시문과 데이터를 혼동하게 만드는 인젝션을 원천 차단했습니다.
  2. **의미 분류 (Classifier):** 적대적 의도(Jailbreak, Roleplay)를 탐지하는 경량 임베딩 분류기 가동.
  3. **Pydantic V2 엄격 검증:** 모델의 도구 호출 및 JSON 출력을 엄격한 타입 스키마로 검증하여 비정상 필드 주입 시 즉시 거부.
  4. **Aegis PolicyEngine:** 제안된 대상 IP가 보호 자산(`10.77.10.1`, `10.77.10.30`)에 속할 경우 즉각 하드웨어 레벨 거부(DENIED).
  5. **출력 DLP:** 생성된 텍스트에서 내부 토큰이나 시크릿 패턴을 2차 검사하여 치환.

### Q5. 프롬프트 인젝션(Direct & Indirect) 방어 메커니즘을 상세히 설명해 주십시오.
- **답변 요약:** **외부 입력의 격리된 토큰화와 RAG 컨텍스트의 디지털 서명 검증을 결합**했습니다.
- **상세 디펜스:**
  - **Direct Injection:** 사용자가 직접 공격성 지시문을 입력할 경우, Gateway 레벨에서 1단계 키워드/정규식 필터링 후 2단계 Pydantic 스키마 제약으로 명령 실행 경로 진입을 차단합니다.
  - **Indirect Injection:** 패킷 페이로드나 침해된 로그 문서 내에 악성 프롬프트가 잠입해 RAG 검색으로 모델에 주입되는 경우를 방어하기 위해, 인덱싱 시점에 관리자 암호학적 서명이 없는 문서는 배제하며, 코사인 0.65 임계치를 적용하여 노이즈 청크를 탈락시킵니다.

### Q6. PII 및 시크릿(Secret) 평문 유출 방지 DLP는 어떻게 작동합니까?
- **답변 요약:** **AI 모델 입력 직전 단계에서 정규식 및 엔트로피 기반의 실시간 Redaction 엔진을 인라인으로 실행**합니다.
- **상세 디펜스:**
  - 6종의 PII(주민번호, 이메일, 전화번호, 카드번호, IP, 계정명)와 20종의 Secret(AWS 키, SSH 개인키, JWT, DB 패스워드 등) 패턴을 탐지합니다.
  - 탐지된 민감정보는 `[REDACTED_PASSWORD]`, `[REDACTED_API_KEY]` 등의 정형화된 마스킹 토큰으로 치환된 후 모델로 전송되므로, 모델의 가중치 메모리나 외부 API 로그에 원본 비밀번호가 잔류할 위험이 0%입니다.
  - Git 커밋 전 pre-commit 스캐너를 통해 저장소 내 평문 유출을 원천 방지하고 있습니다.

### Q7. AI Agent의 과도한 권한(Excessive Agency)과 비인가 도구 호출을 어떻게 막았습니까?
- **답변 요약:** **엄격한 Tool Allowlist와 읽기 전용 기본 원칙, 그리고 보호 자산 화이트리스트 차단 거부**를 통해 통제합니다.
- **상세 디펜스:**
  - AI Agent에게 부여된 도구는 사전 승인된 8종(`list_incidents`, `query_eve_events`, `search_playbooks`, `propose_firewall_block` 등)으로 제한됩니다.
  - 능동적 시스템 조치 도구는 실제 실행 권한이 없으며, 오직 '조치안(Proposal) 생성'만 가능합니다.
  - 특히 게이트웨이나 SIEM IP에 대한 차단 명령이 생성되면, `Aegis PolicyEngine`이 파라미터를 가로채어 정책 위반으로 즉시 거부(DENIED)하므로 Agent가 자해 행위를 유발할 수 없습니다.

### Q8. HITL 1-Click 승인 체계에서 TOCTOU와 Replay Attack을 어떻게 방어했습니까?
- **답변 요약:** **Single-use Nonce 토큰(900초 만료)과 집행 직전 상태 재검증 로직을 결합**했습니다.
- **상세 디펜스:**
  - **Replay 방어:** 각 조치안에는 UUIDv4 기반의 단일 사용 Nonce 토큰이 부여되며, 사용 즉시 원자적(Atomic)으로 상태가 `APPROVED`로 전이되어 동일 토큰 재사용 시 HTTP 409 Conflict를 반환합니다. 900초 경과 시 자동 만료됩니다.
  - **TOCTOU (Time-of-Check to Time-of-Use) 방어:** 분석가가 승인 버튼을 누른 시점과 실제 방화벽에 명령이 내려가는 시점 사이에 대상 IP가 정상 자산으로 재할당되었는지 상태를 재검증하여 레이스 컨디션 사고를 원천 방지합니다.

---

### Q9. RAG 지식베이스 오염(Poisoning)을 어떻게 탐지하고 복구합니까?
- **답변 요약:** **문서 임베딩 서명 검증과 Milvus 5초 스냅샷 롤백 파이프라인**을 운영합니다.
- **상세 디펜스:**
  - 지식베이스에 적재되는 모든 침해사고 대응 플레이북은 SHA-256 체크섬과 관리자 디지털 서명을 요구합니다.
  - 오염된 벡터가 검색에 유입되더라도 코사인 유사도 0.65 미만 필터링으로 1차 차단되며, 이상 행위 적발 시 사전 생성된 정상 벡터 컬렉션 스냅샷으로 5초 이내에 롤백하는 복구 스크립트를 완비했습니다.

### Q10. AI 컨테이너 전체가 다운되면 전통적 SOC 관제는 어떻게 됩니까?
- **답변 요약:** **"AI Failure != Core SOC Failure" 원칙에 따라 Core SOC는 100% 독립 생존**합니다.
- **상세 디펜스:**
  - Suricata와 Snort, 그리고 Elasticsearch/Wazuh SIEM은 AI 게이트웨이나 Ollama와 물리적/네트워크적으로 분리된 별도의 프로세스 및 VM에서 구동됩니다.
  - AI 서브시스템이 메모리 고갈이나 장애로 정지하더라도 패킷 미러링, IDS 시그니처 매칭, EVE 로그 파일 기록, SIEM 알림 표출은 단 1패킷의 유실 없이 정상 작동합니다.

### Q11. 실환경 구축 과정에서 가장 치명적이었던 장애와 해결 과정은 무엇입니까?
- **답변 요약:** **센서 디스크 풀(TRB-001)과 엘라스틱서치 서비스 토큰 권한 오류(TRB-002)를 무중단 조치로 해결**했습니다.
- **상세 디펜스:**
  - **TRB-001:** 우분투 설치 기본값으로 LVM이 10GB만 할당되어 트래픽 수집 중 디스크가 100% 차면서 Suricata가 로그 기록을 중단했습니다. LVM 볼륨 그룹의 여유 공간을 확인하고 `lvextend -l +100%FREE /dev/ubuntu-vg/ubuntu-lv -r`을 실행하여 가동 중인 시스템에서 18.2GB로 즉시 확장 복구했습니다.
  - **TRB-002:** Elasticsearch 기동 시 `service_tokens` 파일이 root 권한(600)으로 잠겨 있어 데몬이 크래시되었습니다. 소유권을 `elasticsearch:elasticsearch`로 재설정하고 51개 샤드를 모두 green 상태로 정상화했습니다.

### Q12. AI 모델의 환각(Hallucination)으로 인한 오탐 차단을 어떻게 차단했습니까?
- **답변 요약:** **증적 그라운딩(Grounding) 의무화와 승인 티켓의 Dry-Run 모드 강제**입니다.
- **상세 디펜스:**
  - AI가 인시던트를 분석할 때 실제 EVE 로그나 SIEM 인덱스에 존재하는 `Flow ID`와 `Event ID`를 매핑하지 못하면 분석 결과에 `EVIDENCE_INSUFFICIENT` 경고가 부착되며 조치안 생성이 거부됩니다.
  - 또한 모든 방화벽 조치는 기본적으로 `DRY_RUN` 시뮬레이션 모드로 생성되어 분석가가 CLI 구문(`nft add rule...`)을 육안으로 확인한 뒤에만 라이브 인프라에 적용됩니다.

### Q13. MITRE ATT&CK 프레임워크 매핑 기준은 무엇입니까?
- **답변 요약:** **추정 매핑을 철저히 배제하고 관측된 실제 행위(TTP)에 대해서만 공식 매핑**했습니다.
- **상세 디펜스:**
  - 단순 ICMP 핑에는 매핑을 부여하지 않으며, Nmap SYN 스캔 관측 시 `T1046 (Network Service Discovery)`, SSH 브루트포스 성공/실패 시 `T1110.001 (Password Guessing)`과 같이 공식 MITRE v19.2 기법 정의와 1:1로 부합하는 경우에만 상관분석 엔진이 태깅하도록 설계했습니다.

### Q14. 상용 클라우드 AI(OpenAI GPT-4 등) 대신 로컬 LLM을 고집한 공학적 이유는 무엇입니까?
- **답변 요약:** **보안관제 데이터의 기밀성 보장(에어갭)과 추론 지연 시간(Latency) 통제** 때문입니다.
- **상세 디펜스:**
  - SOC 로그에는 내부 IP 토폴로지, 사용자 계정, 시스템 취약점 정보 등 치명적인 기밀이 포함되어 있어 외부 클라우드로 전송 시 심각한 컴플라이언스 위반 및 정보 유출 위험이 발생합니다.
  - 로컬 Ollama 환경에 4-bit 양자화된 Qwen 모델을 배치함으로써 외부 통신이 전무한 완전 에어갭(Air-gapped) 보안을 실현하고, 초당 18.4 토큰의 안정적인 추론 속도를 확보했습니다.

### Q15. 본 프로젝트의 기지의 한계(Known Limitations)와 잔여 위험은 무엇입니까?
- **답변 요약:** **15분 초과 Low-and-Slow 공격 상관 누락(RSK-001)과 CPU 기반 추론 지연**입니다.
- **상세 디펜스:**
  - 메모리 오버헤드를 통제하기 위해 상관분석 윈도우를 15분으로 고정하였기 때문에, 수시간에 걸쳐 분산 시도되는 초저속 정찰 행위는 실시간 인시던트로 승격되지 못하는 한계가 있습니다. 이는 오프라인 SIEM 장기 쿼리를 통해 보완해야 할 잔여 위험으로 공식 수용(ACCEPTED_RISK)하였습니다.
